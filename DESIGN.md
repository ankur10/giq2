# Design System: GrowthIQ Briefing

## Overview

**Creative North Star: "The Intelligence Briefing"**

GrowthIQ uses one editorial visual system with three shortlisted options: Precision, Advisory and Mineral, in that order. Advisory is the default, pairing white reading surfaces with ink navy and precise blue. Grove, Midnight, Evergreen, Graphite, Slate, Atelier and Parchment were retired following user feedback. Precision uses stronger sans-serif interface headings and more compact control rhythm while retaining serif article reading. Advisory and Mineral preserve their typography and component rhythm; every option preserves layout breakpoints, data and behavior. Source Serif 4 gives intelligence a considered editorial voice; Source Sans 3 keeps operations clear; JetBrains Mono identifies compact measurements. The product remains an operating workspace with readable evidence and contextual actions.

This is the implemented replacement direction documented from local source evidence. The approved direction does not constitute visual approval of the implementation. Earlier declarations remain in styles.css; this document follows the later Briefing cascade, its responsive overrides and the semantic palette roles in themes.css. Palette values are mirrored in themes.json.

**Key Characteristics:**
- Editorial serif titles and reading copy paired with practical sans-serif controls.
- Theme-aware surfaces and fine borders organize information with minimal elevation.
- Adjacent selection and context keep the evidence near the next action.

## Colors

Color is assigned through shared semantic roles. The frontmatter records normative palette values: unprefixed roles are Advisory, and `precision-` and `mineral-` prefixes identify the corresponding variants. Runtime CSS uses the same unprefixed custom-property names under the selected `data-theme`; themes.css implements these values, mirrored by themes.json. Advisory and Mineral retain their existing type and spacing. Only Precision applies the scoped typography and component refinements described below.

| Variant | Character | Workspace color scheme |
| --- | --- | --- |
| Precision | White/navy, focused blue actions | Light |
| Advisory (default) | White surfaces, ink navy and precise blue | Light |
| Mineral | Cool gray surfaces, charcoal action and intelligence blue | Light |

Advisory takes its navy and focus-blue reference from the [published McKinsey 2020 Design System](https://cdn.mckinsey.com/assets/sketch/McK_DS_core_Artboards.pdf). No logos or brand fonts are copied. This reference guides color character; it does not imply endorsement or a reproduction of the firm’s interface. Precision is an original UI adaptation, not a claimed brand system.

### Primary
- **Primary / on-primary / primary-hover:** paired action colors and hover feedback; independent of reading ink so action foregrounds remain legible in every palette.
- **Accent / accent-light:** links, contextual actions and category fills.
- **Selected / selected-border:** current navigation, objective and signal states.
- **Feature / feature-hover / on-feature / feature-muted:** Studio featured start and notices, with separate foreground roles.
- **Focus:** keyboard outline; the featured start uses on-feature for its inset outline.

### Secondary
- **Green / green-light:** existing positive presence and semantic tags.
- **Amber / amber-light:** existing rating and impact tags.
- **Error / error-light:** field validation and error feedback.
- **Chart 1–4:** existing data marks; retain the underlying data and series meaning.

### Optional dark header
Each palette includes header-surface, header-ink, header-muted, header-control, header-hover, header-border and header-focus. These roles remap topbar surfaces, text, controls, hover, boundaries and focus only when data-header is dark. The topbar uses a native dark color-scheme in that state; sidebar and page content retain their light roles. The selector swatch uses header-focus in the dark topbar. The canvas roles have been lightened; white reading panels remain unchanged.

### Neutral
- **Canvas, surface, sunken and nav:** overall workspace, reading surfaces, contextual panels and navigation.
- **Ink / muted:** main and supporting copy.
- **Line / control-border:** group separators and input boundaries. Control boundaries use their stronger dedicated role.

**The Theme Role Rule.** Apply each palette through semantic roles, including foregrounds, focus, hover, disabled, validation and data marks; do not substitute raw color literals or identify a theme by its swatch alone.

**The Evidence Rule.** Use existing records and honest availability states; visual polish must not imply new data or completed services.

## Do's and Don'ts

### October 2 refinement

The shared refinement layer in `refinements.css`, loaded after the palette styles,
retains all three themes and their font identities. It uses 36px desktop page
titles, 30px mobile page titles, 28px desktop top padding, and a 24px section gap.

the next item partially visible; descriptions remain intact. The research
introduction is left-aligned with its composer, with less vertical whitespace.
Mobile header controls provide 44px targets. This layer supersedes earlier
shared spacing values while preserving the palette-specific typography rules.

Verification for this pass: browser screenshots of Briefing, Studio, and Ask;
page-width containment on 15 screens at 390px, 900px, and 1440px; mobile
navigation; Studio search and brief review; theme/header changes preserving
the current brief. The 67 existing mock-DOM checks and 162 static palette
contrast checks pass. This is not exhaustive browser accessibility or
production-integration verification.

### Do
- Use the locally bundled Source Serif 4, Source Sans 3 and JetBrains Mono families.
- Use semantic action, foreground, selection and contextual-link roles for every theme.
- Keep captured evidence and its availability visible beside related actions.
- Preserve keyboard focus, selected-state semantics and reduced-motion behavior.
- Keep the 15 existing route types, Studio catalog and task workspace, and the existing customer and service access boundaries.

### Don't
- Do not invent KPIs, scores, forecasts, source URLs or completed server actions.
- Do not introduce a promotional hero or decorative card grid into the briefing.
- Do not apply Precision typography or control refinements to Advisory or Mineral; preserve layout breakpoints, data and workflows across all three options.
- Do not describe mock-DOM checks as browser tests or claim visual approval without screenshots.
